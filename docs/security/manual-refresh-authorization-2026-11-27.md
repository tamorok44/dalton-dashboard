# F05 – autorisierter manueller Live-Refresh

Kleiner eigenständiger PR auf Produktionsstand 0608cf5. Öffentliche Ansichten und regulärer Tageslauf bleiben bestehen; GET /api/refresh darf keinen Provider-Zugriff mehr auslösen. POST nur Produktion, mit bisherigem CRON_SECRET für geplante Aufrufe oder dediziertem DALTON_MANUAL_REFRESH_TOKEN für manuelle Aufrufe. Code mind. 32 Zeichen, nicht mit bekannten privilegierten Zugangsdaten wiederverwenden. Vor Authentifizierung kein Redis-/Blizzard-Aufruf; globale manuelle 60-s-Grenze bleibt. Browser-Passwortfeld, Code ausschließlich im offenen Tab, kein localStorage/sessionStorage, kein Query-Parameter, kein Weiterleiten an andere Origins.

**Nicht ohne Setup veröffentlichen:** Vor Merge muss der Betreiber einen eigenständigen zufälligen Aktualisierungscode als sensitive Variable DALTON_MANUAL_REFRESH_TOKEN ausschließlich in Production einrichten und sicher an die Dalton-Gruppe verteilen. Keine bestehende Cron-/Device-/Blizzard-Berechtigung ändern. Kein neues Konto, keine zusätzliche Ressource erforderlich. Ohne Code ist der manuelle Live-Abruf absichtlich gesperrt; automatische Tagesaktualisierung und Anzeigen bleiben. Alte Clients müssen neue Shell laden. Code-Rotation getrennt; gemeinsamer Code ist keine individuelle Benutzeridentität und kein Zugriffsschutz der frei lesbaren Dashboard-Daten. Alte Deployments mit öffentlichem GET müssen betriebsseitig gesperrt werden; Speicherisolation, F04/F18, öffentliche Roharchive separat. Keine produktiven Einstellungen geändert.
